# layouts/

## Responsibility
Site-level Hugo template root. Hugo resolves every template by checking `layouts/` first, then `themes/hugo-brewm/layouts/`. Only the files below exist here, so `baseof.html`, `list.html`, `404.html`, `index.json` and most partials are inherited unchanged from the theme. This layer renders HTML pages, `sitemap.xml`, `robots.txt` and generated alias pages.

## Design
- **Override rule:** a file at the same relative path replaces the theme file wholesale — no merge, no `super`. Everything else falls through.
- `_default/` — `single.html` (single pages without a section layout) and `sitemap.xml`.
- `notes/` — section layouts for `content/{en,pt-br}/notes`; `notes/single.html` shadows `_default/single.html` by lookup order.
- `partials/` — overridden theme partials (`head/meta.html`, `head/js.html`, `head/css.html`, `analytics.html`, `footer.html`, …) plus new ones (`notes/*`, `ascii/lain.html`, `running-lain.html`).
- `shortcodes/` — `hint.html`, `lain-hero.html`; the theme has no equivalents, so these are additions, not overrides.
- `alias.html` — override. The theme's copy dropped `<meta name="robots" content="noindex">`; this one restores it while keeping canonical, meta-refresh and the `rel="me"` link. Every generated alias is therefore non-indexable.
- `robots.txt` — override. `AllowAIRobots = true` emits a permissive `User-agent: *` / `Disallow:`; `false` emits one `User-agent` group per named AI crawler with `Disallow: /`. Always ends with an absolute `Sitemap:` line. The theme only emitted crawler groups when the flag was false and its trailing `Disallow: /` applied to the last group only.
- No `baseof.html` here: inheritance comes from `themes/hugo-brewm/layouts/_default/baseof.html`.

## Flow
Request/output → Hugo lookup (`layouts/<section>/<kind>.<ext>` → `layouts/_default/<kind>.<ext>` → theme equivalents) → `baseof.html` → `block "head"` / `"main"` / `"exclude"` → partials. `sitemap.xml`, `robots.txt` and `alias.html` are standalone outputs and never pass through `baseof`.

Concretely: `/notes/<slug>/` hits `layouts/notes/single.html`; `/posts/<slug>/` and `/about/` hit `layouts/_default/single.html`; both land in the theme baseof. `/sitemap.xml`, `/robots.txt` and every `aliases`-generated page render from the standalone templates here.

Adding an override is a copy-and-edit operation: copy the theme file to the same path, change only what is needed, and keep the block/partial names identical. Deleting an override silently reverts behaviour to the theme.

## Integration
- Theme contract: block names and partial names/signatures must stay compatible with the theme `baseof.html` and the bundled partials (`themes/hugo-brewm/layouts/partials/bundles/{leaf,branch}.html` define `page/*`, `post/*`, `paginator.html`, `taxonomies.html`, …).
- Config read here: `site.Params.AllowAIRobots`, `site.Params.fediverse.{instance,host,username,user}` (alias), `site.Params.{BearMode,ZenMode}` via child templates.
- Subfolder detail: `_default/codemap.md`, `notes/codemap.md`, `partials/codemap.md`, `shortcodes/codemap.md`.
