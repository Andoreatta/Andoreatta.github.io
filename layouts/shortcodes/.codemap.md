# layouts/shortcodes/

## Responsibility
Content-facing shortcodes available to `content/**/*.md`. Hugo resolves `{{< name >}}` to `layouts/shortcodes/name.html`, falling back to `themes/hugo-brewm/layouts/shortcodes/name.html`. This folder holds two **site-only** shortcodes; the theme's `epigraph`, `figure`, `include`, `marginnote`, `marginpar`, `network-graph`, `pin`, `rss`, `section`, `tabular` and `theorem` remain available and are not overridden.

## Design
### hint.html
- Form: `{{< hint info|success|warning|danger >}}…{{< /hint >}}`. `.Get 0` is positional, lowercased, defaults to `info`.
- Label map: `info`→Note, `success`→Success, `warning`→Warning, `danger`→Warning (intentional: no separate "Danger" copy).
- Output: `<aside class="note note--<level>" role="note">` with a `note__label` paragraph and `{{ .Inner | strings.TrimSpace | markdownify }}`.
- `markdownify` re-parses Inner as Markdown and returns `template.HTML`; it does not strip raw HTML, so inline HTML inside a hint survives.

### lain-hero.html
- Paired `{{< lain-hero >}}…{{< /lain-hero >}}`, used by `content/en/_index.md` and `content/pt-br/_index.md`.
- Art column: `partial "ascii/lain.html"` inside `aria-hidden` / `data-pagefind-ignore` wrappers.
- Terminal column: fixed `[ serial experiments // portrait 001 ]` kicker, static prompt line, then `.Inner | markdownify`. The `<a class="profile-more">` written in content survives because of that conversion plus `unsafe = true`.

### markdownify vs safeHTML vs unsafe
- `markup.goldmark.renderer.unsafe = true` (`config/_default/hugo.toml`) lets raw HTML in Markdown through; it is required for `<details>`, `<figure>` and the hero anchor.
- `markdownify` converts a string Markdown→HTML and returns trusted `template.HTML`, so the result is not escaped again.
- `safeHTML` bypasses escaping without parsing; used in page templates (e.g. stripping `disabled=` for task lists), not in these shortcodes.
- The CI content gate is the compensating control: it rejects `<script|iframe|object|embed|base>`, `on*=` handlers, `javascript:` and any shortcode outside `{hint, lain-hero, running-lain, ph-vars}` after blanking fenced and inline code.

## Flow
Markdown page → Hugo parses `{{< … >}}` → shortcode template runs with `.Get`, `.Inner`, `.Page` → Inner goes through `markdownify` → HTML inserted into `.Content` → `_default/single.html` or `notes/single.html` prints `.Content` unescaped (already `template.HTML`). `lain-hero` additionally pulls `partials/ascii/lain.html`; output is not cached.

## Integration
- Partials: `ascii/lain.html` (sole dependency).
- Content contract: `hint` takes one positional level; `lain-hero` is paired and its Inner is Markdown plus limited raw HTML.
- CI gate (`.github/workflows/hugo.yml`): `ALLOWED = {"hint", "lain-hero", "running-lain", "ph-vars"}`. `running-lain` and `ph-vars` are **not** shortcodes — they are partials called by `notes/*` templates — but the gate whitelists their names, so a stray content use would pass the gate and fail later in the Hugo build. Keep the two lists in sync when adding a shortcode.
- Front matter: none read directly; behaviour is driven entirely by shortcode arguments and Inner.
