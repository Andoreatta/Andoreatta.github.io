# layouts/partials/search/
## Responsibility
Site override of the Pagefind UI loader. The theme declares `partials/search/pagefind.html` inline inside `themes/hugo-brewm/layouts/partials/search.html`; this file shadows that definition, replacing the eager `<script src>` + `DOMContentLoaded` init with a lazy, on-demand loader.

## Design
- Contract with the theme: `search.html` renders `<details id="has-search" class="presentation js-details" name="on-deck">` with a `<summary accesskey="q">`, then calls `partialCached "search/pagefind.html" .` when `site.Params.search.pagefind` is true. This partial must not assume it runs after DOM ready — it only wires listeners and checks `details.open` once.
- Lazy load: nothing is fetched until the `<details>` is opened. `initPageFind()` is idempotent (`initialised`, `loading` flags); it creates a `<script>`, sets `src = {{ "pagefind/pagefind-ui.js" | relURL }}`, appends to `document.head`, and only on `onload` constructs `new PagefindUI(...)`. A failed load resets `loading` so the next toggle retries.
- UI options: `element: '#search'`, `showImages: false`, `showSubResults: true`, `showFilters: true`, `translations.placeholder` from `i18n "search"` — filters are what expose the `Section` filter emitted by `layouts/notes/single.html`.
- Accessibility fixup: Pagefind's input ships without a label, so after init `aria-label` and `name` are copied from the rendered `placeholder`.
- No SRI on the injected script: `pagefind-ui.js` is generated by the post-build Pagefind step, so no hash exists at template render time. The file is same-origin and served from the site's own `/pagefind/`, which the CSP already restricts to `'self'`.
- The overlay shell (`#search.on-hull` + `.screening.js-cgpn`) is emitted here so the theme's `search.html` wrapper stays untouched.

## Flow
- `themes/hugo-brewm/layouts/partials/header.html` → `partialCached "search.html" .` → `<details id="has-search">` → `partialCached "search/pagefind.html" .` (this file) → `div#search` + inline script → listener attached to `#has-search`.
- User opens search → `toggle` → `initPageFind()` → `document.head.appendChild(<script src="/pagefind/pagefind-ui.js">)` → `onload` → `new PagefindUI({...})` → Pagefind fetches `/pagefind/pagefind.js` + wasm (allowed by `connect-src 'self'`) and spawns its worker (allowed by `worker-src 'self' blob:`) → DOM injected into `#search` → `aria-label`/`name` copied from placeholder.
- No JS: the theme's `<noscript id="has-search-fallback">` renders the DuckDuckGo (or Mojeek) form; `img-src`/`form-action` in the CSP allow exactly that origin.

## Integration
- Called by: `themes/hugo-brewm/layouts/partials/search.html` (via `partialCached`), reached from `themes/hugo-brewm/layouts/partials/header.html`.
- Depends on: `package.json` (`pagefind` 1.5.2 build step writing `public/pagefind/`), `i18n` key `search`, `layouts/partials/analytics.html` (CSP `script-src`, `connect-src`, `worker-src`), `assets/css` classes `.on-hull`, `.screening`.
- Interacts with: `layouts/notes/single.html` (`data-pagefind-filter="Section"`), `layouts/notes/list.html` and `layouts/partials/notes/cards.html` (`data-pagefind-ignore` scoping), `layouts/partials/ascii/lain.html` (excluded from the index).
